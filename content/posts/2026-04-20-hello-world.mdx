This is a small place for in-progress thinking. Posts live as **MDX files**
under `content/posts/`. Drop one in, push to `main`, and the GitHub Action
takes care of the rest.

## Why MDX

Plain Markdown is great for words. MDX lets the words bring friends —
custom React components — when an idea genuinely needs them.

<Callout type="tip">
  Use callouts sparingly. They're loud, and loud should mean something.
</Callout>

## Code blocks

Syntax highlighting is generated at build time using **Shiki**, so there's
zero highlight JS shipped to the browser:

```ts
type Post = {
  slug: string;
  title: string;
  date: string;
};

export function recent(posts: Post[]): Post[] {
  return [...posts]
    .sort((a, b) => +new Date(b.date) - +new Date(a.date))
    .slice(0, 5);
}
```

## Runnable fences

Fence languages listed in `siteConfig.runnableFences` run as components only
when you open the fence with three backticks followed immediately by `!` and the
language id (for example `` ```!mermaid ``). Without that prefix, the fence is
shown as highlighted source. For example:

```!mermaid
flowchart LR
  A[Write MDX] --> B[Push to main]
  B --> C{GitHub Action}
  C --> D[Build with Vite]
  D --> E[Deploy to Pages]
  E --> F((Live))
```
